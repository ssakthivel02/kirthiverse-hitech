# KirthiVerse P9 — External Pilot Review Pack

> **STATUS: DRAFT — NOT APPROVED FOR PARTICIPANT USE**
>
> This pack is preparation material for external safeguarding/privacy/participant-information review. It is not legal advice, consent, school approval, ethics approval, safeguarding certification, privacy certification, or production readiness.

## Purpose

P9 closes the gap between the software-controlled P4/P5 pilot gates and the real external documents/reviews that P4 must reference before a genuine participant pilot begins.

The software can record a reference and owner attestation. It cannot verify that an external reviewer is qualified, that consent is legally valid, or that an organisation has approved the pilot.

## Pack contents

1. `PILOT_SPECIALIST_REVIEW_CHECKLIST.md` — structured questions for an external safeguarding/privacy reviewer.
2. `PILOT_PARTICIPANT_INFORMATION_DRAFT.md` — plain-language parent/participant information template.
3. `PILOT_DATA_MINIMISATION_RETENTION_DRAFT.md` — local-data inventory, minimisation, retention and deletion decisions to approve.
4. `PILOT_INCIDENT_ESCALATION_DRAFT.md` — operational route for privacy/safeguarding/technical incidents.
5. `PILOT_STOPPING_CRITERIA_DRAFT.md` — explicit conditions that pause/stop a pilot.
6. `PILOT_METRICS_PROTOCOL_DRAFT.md` — what P3–P8 measure, how evidence may be described, and what cannot be inferred.
7. `PILOT_APPROVAL_REGISTER_TEMPLATE.md` — blank register for real external references, reviewer/owner decisions and dates.

## Non-negotiable rule

**Repository presence is not approval.** A merged Markdown file is still a template until the responsible external/organisational process approves the actual final material.

Do not use placeholder references such as `SAFE-REVIEW-001` in a real P4 readiness record.

## Pilot scope this pack assumes

The draft is intentionally narrow:

- small controlled pilot;
- adult-supervised setup;
- participant alias rather than real child name in KirthiVerse local evidence;
- local browser storage rather than a cloud child account;
- no live AI tutor in the current controlled-pilot build;
- bounded deterministic hints/worked guidance only when approved by the pilot protocol;
- no school-wide analytics or cloud class dashboard;
- no claim of production deployment.

If the proposed pilot differs materially, the reviewer should require this pack to be revised before P4 is marked READY.

## External decision points

The responsible reviewer/owner must explicitly determine, outside the app:

- who is accountable for the pilot;
- which jurisdiction/organisation requirements apply;
- who may participate and under what adult/organisational permission process;
- whether any additional consent/assent/information steps are required;
- what information must be provided before participation;
- whether local storage and proposed deletion/retention are acceptable;
- how incidents and participant withdrawal are handled;
- whether the proposed metrics protocol is appropriate;
- what stopping criteria apply;
- whether the pilot may proceed, proceed with conditions, or must not proceed.

## P4 mapping

| Safeguarding/privacy specialist review reference | Real review document/ticket/minutes/reference approved through the responsible process |
| Review date | Actual review/approval date |
| Consent / participant-information pack reference | Final approved participant/parent information and permission-process reference |
| Data-minimisation / retention plan reference | Final reviewed data plan |
| Incident / escalation route reference | Final operational incident route |
| Stopping criteria | Approved pilot stop/pause criteria |
| Metrics protocol | Approved evidence/measurement protocol |

## What P9 does not solve

P9 does not create:

- verified guardian identity;
- legally valid consent by itself;
- school approval;
- research ethics approval;
- safeguarding certification;
- legal compliance certification;
- central tamper-evident telemetry;
- production identity/authentication;
- production readiness.

Those remain external or later-platform responsibilities where applicable.
