## B. Participant / parent information and permission process

- [ ] Participant/parent information is understandable for the intended audience.
- [ ] Prototype status and limitations are clear.
- [ ] Voluntary/stop/withdrawal process is clear where applicable.
- [ ] Benefits are not promised or overstated.
- [ ] Risks/inconveniences are described proportionately.
- [ ] Contact and escalation details are real, current and non-placeholder.
- [ ] The required permission/consent/assent process has been decided externally.

## C. Data minimisation, storage, retention and deletion

- [ ] Non-identifying alias approach is acceptable for the pilot.
- [ ] Real child name/email/school identifier are not required in P3–P8 evidence.
- [ ] Browser/device access controls have been assessed.
- [ ] Browser sync/cloud side effects have been assessed.
- [ ] Export destination/access control is defined.
- [ ] Retention periods are explicitly defined rather than left as `[DECIDE]`.
- [ ] Withdrawal/deletion handling is operationally defined.
- [ ] Data sharing boundaries are defined.
- [ ] Any external service introduced into the process is documented.

Final data-plan reference: `[REAL REFERENCE REQUIRED]`

## D. Safeguarding / wellbeing / incident response

- [ ] Named safeguarding/wellbeing escalation route is present where applicable.
- [ ] Privacy/data incident route is present.
- [ ] Technical integrity incident route is present.
- [ ] Immediate-safety procedure points to the responsible organisation's process, not the app.
- [ ] Stop/pause triggers are clear.
- [ ] Restart authority is clear.
- [ ] Incident narrative is kept outside P6/P7/P8 evidence files where appropriate.

Final incident-route reference: `[REAL REFERENCE REQUIRED]`

## E. Product / technical boundary

- [ ] Current build is described as a controlled-pilot prototype, not a verified production child-account system.
- [ ] No live AI tutor is claimed for the current pilot build.
- [ ] Bounded deterministic assistance setting is understood.
- [ ] Local browser storage limitation is understood.
- [ ] Local evidence is not described as tamper-evident/audited telemetry.
- [ ] P4 is recognised as owner-attestation software, not external approval verification.
- [ ] P5 start/stop/evidence behaviour is acceptable for the proposed protocol.
- [ ] P6/P7/P8 evidence boundaries are understood.

## F. Metrics / external claims

- [ ] Metrics protocol names only intended descriptive measures.
- [ ] Historical data is not backfilled as new pilot evidence.
- [ ] “Completed seven-day observation window” is not described as retention.
- [ ] Activity/lesson counts are not described as learning improvement.
- [ ] Multi-run sums are not described as cohort outcomes.
- [ ] Funding/partner wording is required to pass through P6/P7/P8 evidence checks where applicable.
- [ ] Any future efficacy/retention study will use a separately designed outcome protocol.

Final metrics-protocol reference: `[REAL REFERENCE REQUIRED]`
